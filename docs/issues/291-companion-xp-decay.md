# 동물농장 방치 XP 감소 정책 (#291)

## 이 PR에서 구현한 부분

- `CompanionExperienceDecayPolicy`는 기존 `CompanionNeglectPolicy`와 결합해, 개체별 서버 스냅샷으로부터 시간이 지나면 XP가 얼마나 줄어드는지 계산한다.
- **현재는 순수 정책·단위테스트 단계다.** 기존 서버는 보유 개체를 수량으로만 관리하므로 DB/API/실홈에는 아직 적용되지 않는다.
- `growthXp`: 현재 진화 판정에 쓰는 성장 경험치(방치 시 감소), `totalEarnedXp`: 역사적 총 획득 XP(감소하지 않음).
- 마지막 성공한 돌봄 후 **48시간 유예, 72시간째부터 매 24시간마다 기본 -10XP**.
- 해당 XP 차감 시각에 배부름 또는 청결도가 25 미만이면 **그날 -20XP** (총 20, 추가로 20을 빼는 것이 아님). 이미 건강했던 날에는 과거로 소급하여 추가 패널티를 부여하지 않는다.
- 하한: Lv1=0XP, Lv2=300XP, Lv3=1000XP. 현재 진화 단계는 내려가지 않고 코스튬/희귀도/뽑기 포인트도 유지.
- XP는 하루 최대 100까지 기존 `CompanionGrowthPolicy` 규칙에 따라 획득한다. 성공한 돌봄은 기존 방치 손실을 먼저 반영하고, 그 후 **48시간 XP 감소 유예 타이머를 다시 시작**하며 XP를 획득한다.
- 매분 DB를 쓰는 크론은 필요 없음. 서버가 개체를 읽거나 돌봄/진화 처리할 때, 마지막 처리 시각을 기준으로 지연 계산한다.
- 반복 조회, 정각 경계, 한 시간 미만 잔여 시간, 일수 경계, 위험 상태 전환, 장기 부재, 최종 단계 하한, 진화 자격 재평가, 서버 시계 역행을 테스트한다.
- `Experience`와 `CompanionNeglectPolicy.Snapshot`의 `lastEvaluatedAt`/`lastCaredAt`가 일치하지 않으면 계산을 중단해 이중 차감과 시간 기준 불일치를 예방한다.

## API·DB에 연결하기 전 필수 사항

1. 기존 #287의 개체별 소유 테이블 마이그레이션에서 `growth_xp BIGINT`, `total_earned_xp BIGINT`, `last_evaluated_at TIMESTAMPTZ`, `last_cared_at TIMESTAMPTZ`, `elapsed_hours BIGINT`와 현재 상태 5개 게이지를 함께 저장. 마이그레이션 백필 시 `total_earned_xp=growth_xp` 초기화, 진화 단계에 따라 XP 하한 검사.
2. 인스턴스별 행잠금/버전 검사→방치 상태·XP를 **동일 서버 시각으로 계산**→XP 지급·돌봄 쿨다운 등 검증→동일 트랜잭션에서 업데이트. 조회 시 프론트에 표시되는 값도 두 정책의 동일 스냅샷에서 구해야 함.
3. `POST /api/v1/companions/me/instances/{id}/care`에 유효한 `requestId` 멱등 키를 요구해, 네트워크 재전송이나 연속 누르기에서 중복 XP/상태 변경 방지. 48h 유예 초기화는 실제 성공한 돌봄에 한해 허용.
4. `POST /api/v1/companions/me/instances/{id}/evolve`에서는 방치된 최신 XP·상태로 진화 가능 여부 재평가. 성공 후 새 단계 하한은 영구 보존.
5. 홈의 단일 선택 캐릭터 패널에 `growthXp`, `totalEarnedXp`, `nextEvolution`, `lastCaredAt`를 서버에서 조회하여 표시. 서버 API가 구현되기 전에는 가짜 XP 감소 수치를 사용자 화면에 출력하지 않음.
6. 실제 숫자는 **밸런스 초안**이며, 테스트/유저 피드백 후 버전 관리할 것. 기존 코스튬+캐릭터 결합 뽑기는 수정하지 않음.

## 주의

현재 프론트 홈은 아직 개체별 성장 상태를 가져오지 못한다. 이번 PR만 병합하면 **실제 앱의 XP가 감소하지 않는다.** 실제 감소가 저장되려면 DB, 돌봄/진화 API와 홈 상태 연동 작업이 필요하다.
